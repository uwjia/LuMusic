# 本地音乐播放器 · 实施计划(Rust + React 19 + Vite / Tauri 2)

工作区当前为空,属全新绿地项目。桌面壳采用 Tauri 2(Rust 后端 + Web 前端),这是 Rust+React 组合的标准方案。

## 一、架构分层(核心原则:依赖单向向下,注释全英文)

```
┌─ Frontend (React 19 + Vite + TS) ─────────────────────────┐
│ api/        → 唯一与后端通信层(tauri 实现 + mock 实现)    │
│ stores/     → zustand 状态(player/library/playlist)       │
│ features/   → 功能模块(library/player/playlists/settings) │
│ components/ → 通用 UI;hooks/ → 事件桥接;lib/ → 纯工具     │
├─ src-tauri (Rust) ────────────────────────────────────────┤
│ domain/   → 纯业务逻辑,零 IO:Track/LibraryIndex/Queue/   │
│             Playlist/scan 规则(核心单测区)               │
│ infra/    → IO 适配器:fs_scan(walkdir)、metadata(lofty)、│
│             audio(symphonia 解码 + rodio 输出)、persistence│
│ app/      → 编排层:PlayerService(面向 trait,可 mock 测试)│
│             + #[tauri::command] 薄命令 + AppState + events │
└───────────────────────────────────────────────────────────┘
依赖方向:app → infra/domain,domain 不依赖任何人;前端同理(features 不直接 invoke)。
```

## 三、命令与事件契约(前后端唯一接口)

命令:`scan_library(root)`、`get_tracks(query)`、`player_load(ids,start)`、`player_toggle/play/pause/stop/next/prev`、`player_seek(sec)`、`player_set_volume`、`player_set_mode(shuffle,repeat)`、`player_state`、`playlist_*`(CRUD/增删/排序)、`settings_get/set`。
事件:`player://state`、`player://progress`(约 4Hz 节流)、`library://updated`。播完自动续播:解码器 ended 回调 → service 按 Queue 规则(shuffle/repeat)取下一曲。

## 四、执行步骤(每步含验证门禁)

1. **环境核验 + git init**:确认 node/npm/cargo/MSVC/WebView2(计划模式无法执行命令,这是首个风险点)。若缺 Rust 工具链 → 先报告并给降级方案(前端 mock 模式先行)。
2. **前端骨架**:手写 package.json 等(不用交互式脚手架),`npm install`,vitest 跑通 1 个冒烟测试;React 19 + Vite + TS 严格模式。
3. **Tauri 壳**:Cargo.toml/build.rs/tauri.conf.json/capabilities/icons 脚本,`cargo check` 通过,注册 `app_info` 最小命令。
4. **domain 层 + 单测**:Track 模型、LibraryIndex(去重/搜索/排序)、扩展名过滤与扫描规划、Queue(种子化 shuffle 可断言、RepeatMode off/all/one 的 next/prev 边界)、Playlist 增删重排。纯函数,100% 可测。
5. **infra 层 + 测试**:fs_scan 用 tempfile 造目录树测遍历/过滤/跳过损坏文件;metadata 用内存构造 lofty::Tag 测映射 + WAV 无标签回退文件名;persistence 读写 JSON 缓存(round-trip 测试);symphonia_source 用 hound 生成 WAV 夹具解码断言时长/采样,Seek 精度测试。
6. **app 层**:PlayerService 针对 Scanner/MetadataReader/AudioEngine/Store 四个 trait 编写 mock,单测编排逻辑(自动续播、模式切换、seek 边界、错误传播);commands 保持薄,lib.rs 装配 AppState(RwLock)。
7. **前端数据层**:types、api 双实现、三个 store + usePlayerEvents + lib 工具,全部伴随 vitest(api 全 mock,不依赖 Tauri)。
8. **UI**:App 布局、曲库页(虚拟滚动表格/搜索/排序/双击播放)、底部播放条(播放控制/进度拖拽/音量/shuffle/repeat)、歌单侧栏、设置页(选目录 tauri-plugin-dialog/重扫);组件行为测试。纯 CSS Modules,不引 Tailwind。
9. **集成与收尾**:事件桥接联调、退出时持久化音量/目录、全量验证 `npm run check`(typecheck + vitest + cargo test)、README(架构图/运行说明/测试矩阵)。

## 五、风险与对策

- **工具链未验证**(计划模式只读):步骤 1 首查;缺件即报告,前端可先以 `VITE_API=mock` 纯浏览器模式开发测试,不阻塞。
- **Tauri 构建需 icon/WebView2/MSVC**:gen-icons.mjs 确定性生成图标;缺 WebView2 时给出安装指引。
- **音频 seek 精度**:用 symphonia `SeekMode::Accurate` 自实现 rodio::Source 适配器(约 150 行,成熟模式);WAV 夹具验证。
- **首次 cargo 构建慢**(约 5–10 分钟):预期内,超时调大。
- **损坏/非 UTF-8 文件**:扫描跳过并计入 ScanSummary.warnings,不中断。
- **React 19 生态兼容**:锁定 testing-library@16、zustand@5 等已适配版本。
- 明确非目标(本期不做):歌词、EQ、gapless、标签编辑;专辑封面内嵌提取列为 stretch。

## 六、"行为改动必伴随测试"的落地

- 每步 DoD = 对应测试通过;domain/service/store/组件行为变更必须同步改测试。
- Rust:`#[cfg(test)]` 就地单测,`cargo test`;TS:同目录 `*.test.ts(x)`,`vitest run`;合并入口 `npm run check`。
